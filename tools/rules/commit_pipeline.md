## 1. 直列5段階コミットパイプライン (Fail-Closed)

Gitコミットおよびプッシュの実行時は、以下の5段階を順次検証し、全段合格を確認した後にのみ同期を完了する：

1. **キュー全件検証完了**:
   - `queue/srs_pending_findings.json` の全指摘項目が独立再検証を経て `VERIFIED` であることを確認する（1件でも `PENDING` や未検証項目が存在する場合は中断）。
2. **二重検証通過**:
   - 決定論的リンター（`VerifySRS.exe`）およびローカルモデル（Qwen 27B）の検証合格を確認する。
3. **Zero-Koreanゲート**:
   - ステージング対象の全ファイルおよびコミットメッセージ本文に対して、韓国語正規表現（`[\uAC00-\uD7A3]`）の機械的スキャンを実行し、0文字であることを確認する。検知時は即時中断する。
4. **自発的提示の厳禁およびユーザー要求時限定提示**:
   - エージェントが自発的にコミットメッセージを提示・催促する行為を禁止する。ユーザーから明示的な要求（「コミット準備して」等）を受領した場合にのみ、バイリンガルメッセージ（[日本語原文] と [韓国語対訳]）を1回提示する。
5. **コミット・プッシュ同期実行**:
   - ユーザーから明示的な「コミットして」の最終指示を受領した場合にのみ、直ちに `git commit` と `git push` を同期実行し、リモート同期完了（`To https://github.com/...`）までを確認・報告する。曖昧な表現（「OK」「確認」等）を承認と解釈してはならない。

---

## 2. コミットメッセージ作成基準

- コミットメッセージは、機能のビジネス目的と実装内容のみを正統なビジネス日本語で記述する。
- `(Step 1)`, `(1段階)` 等の機械的なステップ番号やAI生成痕跡は含めない。
- 韓国語の混入を厳禁とする。
